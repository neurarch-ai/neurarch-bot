# Changelog

## 0.5.0 (2026-09-04)

- **New `mode: init`: the config writes itself.** Policy existed end to end (the endpoint enforced it, the bot sent it, the MCP server read it) and a repository only got it if somebody knew to write a `policy:` block by hand, which is a feature nobody switched on. Init walks the repository for `nn.Module` subclasses and `*.neurarch.json` graphs, guesses each model's input shape from the first layer it constructs, traces it, and opens one pull request titled `Add a Neurarch config`.
- **The numbers in the policy block it writes are measurements, and the ones that are not say so.** `max_params` is a round number just above the largest model it actually traced here; `must_fit` is the smallest of T4, A100-40GB and H100-80GB that every traced model actually fits. `forbid_types: [softmax, sigmoid]` is the only suggestion, it is labelled as one, and it arrives commented out. The pull request body carries the table of what was measured and marks every rule **measured** or **a suggestion**, because a generated config is worth exactly as much as the reader's ability to disagree with it line by line.
- **It never commits to a branch anybody works on, and it does nothing at all when a config already exists.** The config arrives as a pull request into the branch the run was on; a repository that already has a `.neurarch.yml` gets no diff, no comment and no branch.
- **Nothing found is silently dropped.** A model whose constructor takes arguments, one no guessed input shape traces, and a class another class in the same file constructs (a building block, not a model) are all written into the file commented out, each with the reason on the line above it.
- **A policy blocker now names the line of `.neurarch.yml` it came from.** `policy: max_params 500K exceeded (1.1M)` left a reader who thinks the rule is wrong with nowhere to go. The comment carries one bullet per violated rule: the rule as written, the file and line it is written on (linked at the pull request's own commit), and whether it is the top-level block or that model's own. A rule the model overrode is quoted from the model's block, which is the one that produced the verdict; a rule with no line in the file says so instead of pointing at a plausible wrong one. Rules the endpoint could not read at all (`unreadable line (max_params: ...)`, `unknown GPU in must_fit (...)`) are located too, since those are the ones a reader most needs pointed at.
- **New `examples/.neurarch.yml`**: every supported key, annotated, with what each blocks or warns on and the message it produces. Linked from the README's install section and from the init pull request body.
- New outputs `init-status`, `init-pr-number` and `init-pr-url`.

## 0.4.0 (2026-09-03)

- **New `train` mode: `/neurarch train` as a pull request comment submits one real GPU run and posts the curve back.** Selected automatically on an `issue_comment` event. Arguments are `epochs`, `dataset`, `gpu`, `model`, `batch`, `lr` and `optimizer`; anything the parser does not recognise is refused rather than ignored, because `epoch=3` silently training the default number of epochs is the failure that rule exists to prevent.
- **Write access, or nothing.** A comment is something anyone with a GitHub account can leave and the API key belongs to whoever installed the Action, so only `OWNER`, `MEMBER` and `COLLABORATOR` can spend it. Everyone else gets one sentence and nothing is submitted. No key is the second refusal: there is no keyless training.
- **Your house rules are checked before the money is.** `POST /api/v1/train` plans the graph on its own and never receives a `policy:` block, so a `max_params` line in `.neurarch.yml` would only be discovered after a GPU was booked. Train mode asks `/api/v1/plan` with the policy first, which costs nothing, and submits only what the repository's own rules allow. The endpoint's 422 stays the backstop for everything structural.
- **A refusal is the product working, and the comment says so in those words.** A blocked design comes back 422 carrying the plan that explains it; the comment quotes the blockers and states that nothing was submitted and nothing was spent. Generating an architecture is cheap and training one that cannot forward-pass is not, which is the whole reason the verifier runs first.
- **No GPU worker means 503, never a simulation.** The endpoint refuses to fall back to a heuristic curve and so does the bot: a simulated curve posted into someone's pull request as a training result is a fabricated measurement published under our name.
- **One comment per run, edited as the epochs arrive.** Keyed on `<!-- neurarch-train:<job_id> -->`, so it is never confused with the plan comment and two runs on one pull request each keep their own. Polled every 20 seconds up to the new `timeout-min` input (default 20). A timeout stops the comment following the run, not the run.
- **The curve is a unicode sparkline and a table, not a picture.** GitHub's comment sanitizer strips `src` from any `<img>` carrying a `data:` URI, in markdown and in raw HTML alike, and drops inline `<svg>` outright. Measured against a real comment on a real repository before the choice was made.
- **A failed training run never fails the check.** The trainer's error is reported, trimmed, as what it is: a fact about the model, not a verdict on the pull request. The final comment carries the per-epoch table, the final metric in bold, wall clock, measured cost, whether the outcome ledger row was written, and therefore whether the next plan for this structure will quote this run.
- The caller must check out the pull request head: an `issue_comment` event checks out the default branch, which is not the model anyone asked about. The README's workflow uses `ref: refs/pull/${{ github.event.issue.number }}/merge`.
- **A finished run with no cost says so.** The endpoint prices a run from its wall clock at the rate of the card on the job row, and a row with no card recorded comes back with a null `est_cost_usd`; the first live run did exactly that. A missing line would read as "free" to whoever pays the bill, so the row is printed either way.
- New inputs `timeout-min`; new outputs `job-id` and `train-status`.

## 0.3.0 (2026-09-03)

- **New `fix` input.** On a blocker, the bot patches the model, verifies its own work, and opens a pull request. It runs after the plan comment is posted, because the plan reaches the pull request whether or not a fix turns out to be possible.
- **Two sources of patches, in order.** The **exact patch** comes from `suggest_fix` in `neurarch-mcp`: it reads the `.py`, lints it and returns a unified diff for the rules that pin a number or an order, at no model call and no key. That CLI has no one-shot `suggest_fix` subcommand, so the bot speaks the server's stdio JSON-RPC directly (two writes, two reads, standard library, no MCP client library on the runner). The **proposal** comes from `POST /api/v1/fix`, which is metered against the API key owner's agent quota and is therefore **skipped outright when no `api-key` is set**, with the comment saying the source was skipped rather than pretending it was tried.
- **Nothing is pushed that the bot's own gate has not accepted.** The patch is applied to a scratch worktree at the pull request's head, the model is traced again and planned again, and the result is accepted only if the new plan is legal AND the parameter count is within 10 percent of that head. A "fix" that deletes half the model turns every blocker green and is not a fix. Up to 3 rounds, feeding the remaining findings back in; a round that reduces the blocker count is kept and built on, a round that does not is thrown away.
- **The fix pull request goes into the original pull request's head branch**, not the default branch: the fix belongs on top of the change that broke it. Branch `neurarch/fix-pr<N>`, title `Fix the blocker in #<N>`, body carrying both plans side by side and naming which source produced the patch. One line is added to the plan comment linking it; on failure, one line saying what was tried and why it was rejected.
- **Never a second fix pull request for the same original.** The branch name is derived from the pull request number, so a re-run pushes the same branch and updates the pull request already open on it.
- **A patch is refused before it is applied** if it targets a file `.neurarch.yml` does not list, is absolute, or climbs out of the repository. The bot has a write token; the allowlist is the config's own model files and nothing else.
- New `github-token` input, defaulting to `${{ github.token }}`. A pull request opened with the default token **does not trigger workflows**, so the fix pull request arrives with no bot check of its own; pass a PAT to get one.
- **New `policy:` block in `.neurarch.yml`**, sent with every plan: `max_params`, `must_fit`, `max_layers`, `forbid_types` and `require_types` are blockers, `max_memory_gb` and `max_cost_usd` are warnings, each quoted as you wrote it. A model's own `policy` merges over the top-level one key by key, so tightening one line does not drop the rest. It needs no API key, because a policy can only make the verdict stricter.
- **The exact source takes its answer the moment it lands** rather than waiting for the MCP server to exit. A stdio server is allowed to sit there after it has answered, and waiting for EOF turned a call that had already succeeded into a reported timeout on the first live run. `~/.npm` is cached so the `npx` download is not the slowest thing in the step.
- **The fix commit carries the patch's own files and nothing else.** Tracing the model in the scratch worktree imports it, which writes `__pycache__/*.pyc` next to the source; the first fix pull request this bot ever opened carried one, because the commit was `git add -A`.
- **One repository setting is needed, or the pull request 403s.** GitHub blocks an Action from opening a pull request unless "Allow GitHub Actions to create and approve pull requests" is on. The branch pushes, the API call comes back 403, and the bot says it pushed the branch but could not open the pull request. The README says where the toggle is.
- New outputs `fix-status`, `fix-pr-number`, `fix-pr-url`.

## 0.2.0 (2026-09-03)

- New `mode` input. The default `pr` is unchanged. `mode: report` traces **every** model in the config at the current commit, with no base and no diff against a branch, and upserts one issue titled `Neurarch weekly model report`.
- The report body carries: a table of every model (layers, params, shape, will it run, GPU fit, estimated cost, fingerprint); every blocker and warning across all models, quoted in full; what changed since the last report; and documentation drift.
- **Changed since the last report** reads the previous report's numbers back out of the issue it is about to overwrite. The body ends in a machine-readable block, `<!-- neurarch-report-data {...} -->`, so the comparison is against measured numbers and not against parsed prose.
- **Documentation drift** looks for a `MODEL_CARD.md` or `README.md` next to each model file and reports any parameter count written there that the trace disagrees with by more than 1 percent. A doc that names other listed models and not this one is skipped, so one card shared by a folder does not accuse every model in it; a doc where any number agrees is treated as right and stays silent.
- **Report mode never fails the job.** A report is a record, not a gate: blockers are printed, the run stays green. A report that crashes outright still fails, because a report that did not happen is a failure.
- The issue is upserted: an open issue with that exact title is updated in place and gets a short comment naming what moved, so the record is one issue with a history and not a weekly pile. A new issue gets the `neurarch` label when the repository already has one, and a repository without it is not a failure.
- New outputs `issue-number` and `issue-url`.

## 0.1.0 (2026-09-03)

First release.

- Composite GitHub Action: on every pull request, trace each model listed in `.neurarch.yml` that the PR touches (HEAD and base), POST both graphs to `https://www.neurarch.com/api/v1/plan`, and post one comment per PR with the plan for every affected model: params, cost, GPU fit, whether it will run, and the deltas against the base branch.
- The comment is upserted (marker `<!-- neurarch-bot -->` on the first line), so a PR carries one comment that follows its commits.
- A blocker fails the check; `fail-on-warn` extends that to warnings.
- Static fallback: when a model cannot be traced (import error, bad input, a constructor that raises), the comment carries the traceback tail and a static read of the file by neurarch-lint. A blocker found that way still fails the check; the trace failure by itself does not.
- Outputs: `legal`, `blockers`, `warnings`, `plans-json`.
